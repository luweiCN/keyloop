# KeyLoop 统计驾驶舱重设计

日期：2026-08-20

状态：已确认（2026-08-20）

范围：产品与交互设计，不包含本轮代码实现

## 1. 设计结论

统计页不应继续做“八个标签页里的文字报告”，而应成为一个终端原生的**训练驾驶舱**：用户进入后几秒内能看懂今天练得够不够、目标是否在推进、哪类输入正在进步、哪些击键结构仍是瓶颈，以及下一轮为什么这样安排。

视觉上的“酷炫”来自真实数据形成的终端图形、可移动的数据焦点、键盘热力图和清晰的状态反馈，不来自大号数字、卡片墙、霓虹装饰或持续动画。

## 2. 已确认的产品约束

- KeyLoop 是固定 96 列宽的 Bun / OpenTUI 终端产品，核心操作必须只靠键盘完成。
- 已有主题以终端默认前景/背景为底，绿色为主强调，青色为信息色，黄/红为警告和错误。
- 练习数据只保存在本机；统计页不需要云端、账号或同步状态。
- 薄弱诊断的唯一合法粒度是击键结构：键位、手、字符转移、固定符号组合、字符类和技能维度。
- 具体错词、错句、文章和代码片段不是个人弱点，不应继续作为统计页的诊断排行榜。
- 当前历史含大量旧格式和不可计速记录。任何趋势图上线前，必须先建立统一的数据资格规则。

## 3. 用户进入统计页要回答的四个问题

| 问题 | 一级视图 | 首要答案 |
|---|---|---|
| 我现在练得怎么样？ | 总览 | 今日练习量、当前目标状态、最近表现、下一轮重点 |
| 我真的在进步吗？ | 趋势 | 同一训练形态内的 WPM / 正确率变化，以及练习稳定性 |
| 到底哪里薄弱？ | 技能 | 单键 confidence、结构维度状态、样本可信度 |
| 某一天具体发生了什么？ | 历史 | 活跃日历、当天汇总、会话明细 |

一级导航由当前 8 个视图收敛为 4 个：

1. `总览 / Overview`
2. `趋势 / Trends`
3. `技能 / Skills`
4. `历史 / History`

原有内容的归并规则：

- `today`、`comprehensive` 进入总览和历史。
- `modules` 变成趋势页中的“训练投入构成”，不再单独占页。
- `code` 作为训练形态筛选项，与键位、单词、符号、句子、文章并列。
- `keys` 升级为技能页的物理键盘热力图。
- `tokens` 从诊断导航中移除；具体 token 只允许在单次会话上下文中查看，不参与“弱项”或下一轮推荐。
- `daily` 升级为历史页的活跃日历与会话列表。

## 4. 三层统计模型

页面必须明确区分三种经常被混用的维度。

### 4.1 训练习惯：什么时候、练了多久

用于回答“练得是否持续”，按**日历时间**统计。

- 今日活跃分钟 / 今日建议分钟
- 过去 30 / 90 天活跃日数
- 总活跃分钟
- 每个活跃日的中位练习分钟
- 产品模块的活跃时长构成：基础输入、日常英语、编程基础、自定义词库、代码实战

图表：目标 bullet bar、30 日活动条、12 周活动日历、模块时长构成条。

### 4.2 训练表现：同一种输入形态是否进步

用于回答“速度和质量是否变好”，按**合格会话序列**统计，不能把不同难度形态直接横向排名。

训练形态固定为：键位、单词、符号、句子、文章、代码。

- 当前形态 EWMA WPM
- 当前形态加权正确率
- 最近 10 次与前 10 次的 WPM 差值
- 最近 10 次与前 10 次的正确率百分点差值
- 趋势状态：进步 / 稳定 / 下降 / 数据不足

图表：单指标折线/点图、每形态小型 sparkline。WPM 与正确率通过 `M` 切换，绝不使用双 Y 轴。

### 4.3 击键诊断：哪种结构拖后腿

用于回答“下一轮为什么练这些”，必须与训练引擎使用同一套信号。

- 单键：samples、error rate、avg interval、effective time、confidence
- 结构维度：home/top/bottom row、left/right hand、digits、symbols、capitalization、word fluency
- 每个结构维度：status、trend、EWMA error rate、EWMA speed、events
- 数据覆盖：已评估键数 / 总键数、未评估原因

图表：物理键盘 confidence 热力图、结构维度水平状态条和趋势符号。

暂不把“字符转移”和“固定符号组合”伪装成现成指标：当前训练引擎尚未形成对应的统一诊断账本，且语言特定组合缺少可靠的结构化语言字段。它们应在诊断模型先落地后再进入统计页。

## 5. 指标口径

### 5.1 数据资格分层

每条记录先进入以下三种状态之一，不能在渲染层临时猜测：

- `performance_eligible`：可参与 WPM / 正确率趋势。
- `activity_only`：旧记录只可贡献练习日期或近似时长，不参与表现趋势。
- `excluded`：没有可信时间或输入样本，只保留在数据覆盖说明中。

推荐的表现资格规则：

- `active_ms >= 15_000`
- `typed_len >= 25`
- `correct_chars > 0`
- 由 `correct_chars / active_ms` 重算出的 WPM 有限且不超过 300

不截断异常值；异常记录直接退出趋势，并计入数据覆盖说明。`partial` 会话只要达到样本门槛仍可参与表现统计，但在历史明细中标注“未完成”。

### 5.2 速度

聚合 WPM 必须按总字符和总活跃时间重算：

`sum(correct_chars) / 5 / (sum(active_ms) / 60_000)`

不能平均每次会话的 WPM，也不能在新趋势中以 `duration_ms` 冒充 `active_ms`。CPM 只在最后的展示层由 WPM × 5 转换。

### 5.3 正确率

使用输入事件数量加权：

`sum(correct insert events) / sum(insert events)`

旧记录没有事件时，可使用 `typed_len × accuracy` 的兼容路径，但必须保留来源标记。

### 5.4 比较窗口

- 习惯：7 / 30 / 90 个日历日，默认 30 日；无练习日显示为 0。
- 表现：最近 10 / 30 个合格会话，默认最近 10 次；不同训练形态分别计算。
- 结构维度：沿用现有最近 10 个相关会话和 EWMA 半衰期。
- 单键 confidence：直接展示训练引擎的 canonical signal，避免统计页与组卷逻辑说不同的话。

### 5.5 明确不做“综合分”

不再制造一个 0–100 的“今日综合分”。它会把时长、速度、正确率和难度混成无法解释的数字。总览只并列呈现三件事：练习量、表现、诊断结论。

历史最高 WPM、最低错误率、总错误数也不再作为首屏 KPI：单次最好成绩容易受短会话和异常数据影响，错误数又受文本长度影响。这些值只保留在历史明细或经过资格约束后的次级统计里。

## 6. 四个视图

### 6.1 总览：先给结论，再给证据

默认首屏按以下顺序组织：

1. 今日活跃时长与建议时长的 bullet bar。
2. 若设置目标，显示当前形态 WPM → 目标 WPM、期限与可达状态；无目标时该行替换为最近训练状态，不出现空卡。
3. 最近 30 日活动条，以及活跃日数 / 总分钟。
4. 今日或最近一次的 WPM、加权正确率、相对近期基线变化。
5. “下一轮重点”结论，最多展示 3 个结构维度和 3 个具体键，并给出一行可追溯证据。

建议线框：

```text
┌ 总览 ───────────────────────────────────────────────────────────────────────┐
│ 今日  ████████░░░░  12.6 / 建议 20 分钟      过去 30 天  2 活跃日 · 25 分钟 │
│ 代码目标  30.1 WPM  ━━━━━━━━━●━━━━━━━━○  50 WPM      数据积累中              │
│ 活动  · · · · · · · · · · · · · · · · · · · · · · · · ▓ · · ░ · ·        │
│ 最近  WPM 35.0  ↑2.4 / 前 10 次      正确率 94.2%  ↑0.8pp                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ 下一轮重点  符号 · 大写 · Bottom row                                         │
│ 证据  符号错误率 22.0% · # confidence 0.41 · 最近趋势稳定                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

动态标题应直接陈述结论，例如“符号仍是主要瓶颈，代码速度保持稳定”，而不是“今日综合”。

### 6.2 趋势：一次只比较一个问题

布局：

- 顶部筛选：训练形态、指标、样本窗口。
- 主图：WPM 或正确率的终端折线/点图，带最小值、最大值、单位和选中点。
- 选中点详情：日期、形态、合格会话数、WPM、正确率、活跃分钟。
- 下方 6 行形态 small multiples：当前 EWMA、趋势状态、最近 sparkline。
- 底部一条产品模块时长构成，回答“时间花在哪里”，但不拿模块 WPM 相互排名。

表现图没有会话时显示空缺，不把“没练”画成 0 WPM，也不跨长空档连线。活动时长图中的 0 才代表当天没有练习。

### 6.3 技能：把键盘变成诊断地图

上半区显示标准物理键盘行。每个键同时用两种方式表达状态：

- 字符密度：`▓` 更弱、`▒` 待加强、`░` 达标、`·` 数据不足。
- 语义色：红/黄/绿/灰；青色只表示当前选中键。

强度只负责把低 confidence 排出视觉层次，不新增另一套“弱项阈值”；`confidence >= 1` 仍是唯一达标分界，低于 1 的字符按当前可评估范围归一化深浅。

同一个物理键上的基础字符与 Shift 字符不能粗暴合并。例如 `3` 和 `#` 共用键帽，但肌肉动作不同。键帽显示两者中更弱的状态，选中详情分别列出 `3` / `#` 的信号。无法映射到标准 ASCII 键盘的字符进入单独的“其他字符”行，不塞进错误键位。

方向键在物理键盘上移动焦点，旁边详情固定显示：

- confidence
- effective time / avg interval
- error rate
- samples
- 数据是否足够

下半区按训练逻辑顺序展示结构维度，而不是按原始 WPM 从高到低排序。每行显示 `status + trend + error rate + speed + samples`，弱项置顶，但保留其原始类别标签。

不提供现有 5 种循环排序；默认直接突出 canonical weakest keys。高级用户仍能通过选中键查看全部原始数值。

### 6.4 历史：日历定位，列表解释

- 顶部为最近 12 周活动日历，字符深浅编码当天活跃分钟。
- 左右方向键切换日期；Home / End 跳到最早 / 最新有数据日期。
- 当天摘要显示：活跃分钟、合格会话数、加权 WPM、加权正确率、模块构成。
- 上下方向键选择当天会话；Enter 展开详情。
- 会话详情显示：时间、训练模块/形态、完成状态、active/idle、WPM/raw WPM、正确率、退格数和数据资格。
- 默认不显示目标文本或最终输入；具体内容只在明确展开的本地会话上下文中出现，且不被命名为弱点。

## 7. 交互模型

| 范围 | 按键 | 行为 |
|---|---|---|
| 全局 | `1–4` / `Tab` / `Shift+Tab` | 直达或循环四个一级视图 |
| 全局 | `Esc` | 返回主菜单 |
| 趋势 | `↑/↓` | 选择训练形态 |
| 趋势 | `←/→` | 移动图表数据焦点 |
| 趋势 | `M` | WPM / 正确率切换 |
| 趋势 | `[` / `]` | 10 次 / 30 次窗口切换 |
| 技能 | `↑/↓/←/→` | 在物理键盘上移动选中键 |
| 历史 | `←/→` | 切换日期 |
| 历史 | `↑/↓` | 选择当天会话 |
| 历史 | `Enter` | 展开 / 收起会话详情 |
| 历史 | `Home` / `End` | 最早 / 最新有数据日期 |

任何交互都必须立即更新数字说明行；图形不是唯一反馈。焦点通过 `▌`、青色或反显表达，不使用持续闪烁或装饰动画。

## 8. 视觉方向

- **颜色策略**：克制的产品界面 + 有限语义数据色。底色和绝大多数文字沿用终端主题；颜色只编码状态、系列和焦点。
- **场景句**：程序员在一次练习结束后、昏暗工作环境中的终端里花一两分钟复盘，精神集中，希望立刻知道接下来练什么。
- **参考锚点**：
  - `btop`：终端原生的数据密度、字符图形和即时反馈。
  - GitHub contribution graph：一眼读懂练习稳定性的活动日历。
  - `keybr`：以单键 confidence 解释薄弱和训练方向。
- **禁止**：饼图、甜甜圈图、雷达图、双轴图、仪表盘 gauge、3D、巨型 KPI、同尺寸卡片墙。

小型趋势使用 `▁▂▃▄▅▆▇█` sparkline；主趋势图使用可测试的 box-drawing / Braille 字符，并始终配精确数值行。条形图从 0 起始；折线图可使用非零基线，但必须标出上下界。

## 9. 关键状态

### 完全无数据

不展示 4 个空标签。直接解释“完成一次练习后会看到什么”，并用空键盘轮廓预告技能页。

### 有练习、数据不足

活动时长照常显示；WPM、趋势或单键 confidence 显示“还需 N 个样本”，不显示 0 或伪造趋势。

### 稀疏历史

活动图保留真实空白日；表现图按会话序列展示，不跨空档暗示连续进步。

### 混合旧数据

页面底部显示可理解的数据覆盖，例如“210 / 1,277 次记录可用于速度趋势；旧记录仍保留在历史中”。按 `I` 可查看资格口径，但不让提示抢占首屏。

### 目标状态

覆盖无目标、冷启动、正常推进、不可达、已达成五种状态。不可达时只陈述事实和已有替代方案，不用红色制造焦虑。

### 受限终端高度

- 28 行及以上：展示完整视图。
- 20–27 行：压缩次级说明和图表高度，保留数值与焦点。
- 低于 20 行：使用手动 viewport / 滚动，而不是继续挤压到不可读。

96 列是现有产品宽度；中文和英文都要做显示宽度测试。颜色不可作为唯一编码，并验证 16 色与单色退化效果。

## 10. 技术结构建议

### 10.1 先有 typed model，再有图

不要让新 UI 继续消费 `string[]`。新增纯函数统计模型，把计算与中英文格式化彻底分离：

- 数据资格与覆盖
- 按日 buckets
- 按训练形态的合格会话序列
- 模块时长构成
- 当前 SkillProfile / key signals
- 目标与下一轮建议

日历 bucket 一律使用用户本地时区，避免 UTC 日期把深夜练习分到错误的一天。

路由交互状态建议使用判别联合，避免当前大量可选字段形成非法组合：

- `overview`
- `trends { form, metric, window, cursor }`
- `skills { selectedKey }`
- `history { dayIndex, sessionIndex, expanded }`

统计数据进入页面时构建一次；移动焦点时只改变选择状态，不重新遍历整个 18 MB 历史文件。语言和 WPM/CPM 只改变展示层。

### 10.2 只增加本页真正需要的图表原语

不引入通用图表框架或外部依赖。只做经过当前页面验证的纯函数/组件：

- sparkline
- selectable line/point chart
- activity strip/calendar
- horizontal composition bar
- physical keyboard heatmap

每个原语输出可预测的字符行，再由 OpenTUI 负责颜色和焦点；这样能在不启动真实终端的情况下做单元测试。

### 10.3 兼容现有 CLI

现有 `keyloop report today` 和字符串报告函数先保持行为不变。TUI 使用 typed model 完成迁移后，再单独评估哪些旧 stats line functions 已无调用方；本次重设计不顺手改 CLI。

## 11. 实施切片

### Slice 1：数据可信度与 typed model

- 定义资格规则、覆盖计数、日/形态/模块聚合。
- 对异常旧记录、零时长、超短会话、partial、CPM、时区边界写测试。
- 用本机规模和 5,000 条合成记录验证构建成本。

验收：任何图表输入都不含不可信 WPM；旧记录不会消失，用户能看到其覆盖状态。

### Slice 2：总览纵切

- 收敛到 4 个一级视图。
- 上线今日时长、目标 bullet、30 日活动条、近期指标与下一轮重点。
- 完成无数据、数据不足、无目标/有目标状态。

验收：用户无需切页即可回答“今天怎么样、下一步练什么”；96×24 中文/英文均不溢出。

### Slice 3：趋势纵切

- 上线形态筛选、WPM/正确率切换、10/30 次窗口、选中点详情。
- 增加六形态 small multiples 与模块时长构成。

验收：不连接缺失数据、不使用双轴；所有点都可通过键盘读取精确值；不同形态不做无意义的绝对排名。

### Slice 4：技能纵切

- 上线物理键盘 confidence 热力图、方向键导航与结构维度列表。
- 复用 canonical key signal 和 SkillProfile，不在页面内另造弱项算法。

验收：无颜色也能区分弱/达标/未评估；选中键的 confidence、错误率、耗时和样本数一致；统计结论与下一轮训练信号一致。

### Slice 5：历史纵切与旧页退场

- 上线 12 周活动日历、日期/会话选择、详情展开。
- 删除 TUI 中旧的 today/comprehensive/modules/tokens/code/daily 平级导航。
- 具体 token 退出诊断展示。

验收：可从日期定位到任意会话；partial/legacy/eligible 状态清楚；不把具体内容命名或排序为弱点。

### Slice 6：质量门

- 全量中英文与 WPM/CPM 测试。
- 16 色、单色、20/24/28+ 行终端检查。
- 真实数据性能检查和焦点/导航回归。
